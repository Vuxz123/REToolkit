# Native event observations and UI runtime provider

The SS2 startup is blocked by a scoped function flowing beyond its accessor and
by an exported UnityEngine.UI.dll containing inert Slider methods.

1. Add explicitly bounded instruction evidence, emitted by the existing native
   provider and bound to exact build/program/run/revision. Event storage may use
   a contiguous AArch64 instruction window ending at the next verified dump RVA.
   This records accessor provenance, not complete function/control-flow proof.
   Preserve metadata association, independent field-use review and later Unity
   checks. Do not alter function boundaries, fall-through or no-return flags.
2. Add a narrow runtime-provider plan/apply route for an explicit local DLL.
   Inspect metadata/IL without executing the target, compare assembly identity,
   existing type/API/serialized fields, and retain original DLL metadata. Save
   immutable replacement bytes and a staged inventory. Never silently remove a
   DLL or install a competing source package. Reuse the shared recovery artifact
   and subsequent scoped Unity/data/behavior verification.
3. Test invalid/tampered/incomplete evidence and incompatible providers, then
   inspect the exact installed Editor UI candidate. Keep gameplay unverified.
